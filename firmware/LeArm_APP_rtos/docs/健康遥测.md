# 健康遥测 schema 1（HEALTH_STATE 0x83）

2026-11-12迁入RosCar说明：本文保留健康协议及先前验证记录；最新完整启动修复、仓库范围和Keil入口见 [../README.md](../README.md)。下方旧路径、“未完整链接”和“无独立远端”表述为迁入前历史。

本修改仅附加观测，不改变运动许可、安全锁存、STOP/Boot握手或执行器控制。串口仍由SerialTask唯一发送，不混入printf。原44字节前缀原样编码，旧fault_flags仍是原HealthTask的历史/汇总语义（包含旧ESTOP位）；新active_faults排除ESTOP，它只表示安全状态。

资源timestamp可能比附加动态年龄旧约100ms；附加年龄以同一临界区内HAL_GetTick计算（不使用可能在抢占/I2C前取到的旧任务now），uptime_ms可作为其参考。若输入时间在未来半个tick范围，elapsed保护返回0，正常短区间32位回绕仍有效。主机不要把帧传输年龄再叠加到采样时50ms deadline后倒推软件故障；整帧过期应单独显示。

## 当前与未知

- active MOTOR来自当前底盘输出调用失败、编码器/电压当前采样失败或最后成功采样超过100ms；相应成功调用会清当前来源，历史仍保留。计数连续失败只覆盖采样轮，不混入输出调用。
- active COMMAND_TIMEOUT来自最后实际取到的底盘速度命令超时；新命令重建时间。未收到命令为未知，不报命令超时。该字段不代表安全许可或机械臂命令租约，STOP也不清除最后速度命令的观测历史。
- active HEALTH来自已知心跳年龄超期（100/50/100/500/250ms）；未收到过的心跳保持未知，valid mask为0，不伪造年龄。资源高水位是历史，不把历史低栈/低堆直接当当前故障。
- Arm初始化失败实际观测为ARM故障；dispatch期间标2，返回后0未知。无反馈query，不能把函数返回当物理动作完成，也不能因空闲时不query报故障。
- 串口CRC/overflow等累计计数仍在前缀；CRC校验失败由纯协议parser的饱和crc_error_count记录，SerialTask按consume前后增量计UART_CRC，CRC丢帧不再重复记UART_FRAMING，其他COBS/格式丢帧仍记FRAMING。last_drop_was_crc确保parser计数饱和后也不会误分类。没有持续错误状态的可靠解除机制，因此不把累计错误伪装成active协议故障。TX失败有独立计数。
- 安全事件在原mutex内复制到健康观测，健康API不调用安全状态机；健康快照所有字段、心跳时间/有效位和动态年龄在一个临界区一致复制。

## 实现/构建

新增RobotHealthWire.c/h：`size_t robot_health_wire_encode(const HealthState_t*, uint8_t*, size_t)`，成功128，参数/容量错误0。纯C、不依赖RTOS/HAL，可host编译。HealthState只作逻辑结构，不按sizeof直接发送。

RobotHealth新增当前来源、采样、命令、机械臂观测、安全事件、历史与TX丢帧API。SerialTask使用128缓冲并调用纯编码器。Keil实际LeArm.uvprojx已加入RobotHealthWire.c；顶层CMake加入该源，但原CMake缺其他业务/厂商源及应用链接配置，本修改未修复整个CMake构建链，不声称完整链接产物可烧录。
