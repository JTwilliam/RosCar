# 运行手册：按执行主机选择工作区

2026-11-10更新：运行指令已分开，避免在上位机误启动采集，或在树莓派误启动RViz。

| 你正在使用的机器 | 进入目录 | 完整操作说明 |
| --- | --- | --- |
| Ubuntu22.04 Desktop + Humble上位机 | `~/RosCar/host_ws` | [host_ws/README](../host_ws/README.md) |
| Raspberry Pi4B + Ubuntu22.04 + Humble | `~/RosCar/pi_ws` | [pi_ws/README](../pi_ws/README.md) |
| WSL离线学习 | 对应工作区 | 各自README的编译/测试部分，不运行真实硬件 |

上位机只显示；树莓派运行STM32桥、IMU、雷达、EKF和安装TF。数据通过DDS传输，上位机不需要编译树莓派传感器包。

## 更新后的入口

- 上位机 `cd ~/RosCar/host_ws` → `bash build.sh` → 配置host.env → `bash start.sh`。
- 树莓派 `cd ~/RosCar/pi_ws` → `bash build.sh` → 配置pi.env → `bash start.sh all`。
- 树莓派调试 `bash start.sh imu|chassis|lidar|imu-tf|lidar-tf`，每个长期命令单独终端；不与all重复运行。
- 两端均可先加 `--dry-run` 验证配置和依赖，不启动节点。

## 从旧目录更新

雷达源码原位于lidar_ws/src，现在与其他采集包统一放到pi_ws/src，ldlidar和ldlidar_driver仍相邻。旧lidar_ws以及旧build/install/log可能保留本地历史数据，不自动删除，也不再source。

请新开终端，仅加载系统Humble后运行对应build.sh；它使用新build/host_runtime或build/pi_runtime，避免CMake缓存含旧源码位置。不要把旧build/install复制到新目录，也不要在.bashrc继续自动source旧lidar_ws/install。查看.bashrc后按实际需要自行调整。

旧scripts/robot.env中的DDS、设备路径和实测安装数值应分别复制到host_ws/host.env、pi_ws/pi.env，不共享机器相关绝对路径。脚本没有自动安装依赖、改网卡、调时钟、SSH登录或目标板部署。

## 机器人约定

轮序FR、RR、FL、RL，vx前进、vy向左、wz逆时针；EKF输入/odom与/imu/data，输出/odometry/filtered。仅EKF发布odom→base_link，安装TF依据实测。IMU启动校准保持静止约3秒。停止先让底盘停止运动，再Ctrl+C采集与显示。

网络/DDS及常见故障见[双机部署总览](双机部署与启动.md)。历史验证不是本次实车结果，详见[进展与验证](进展与验证.md)。
