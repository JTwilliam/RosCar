# 树莓派麦轮底盘、IMU、EKF 与 RViz 运行手册

适用环境：树莓派 4B（Ubuntu Server 22.04、ROS 2 Humble）运行传感器和融合；Ubuntu 22.04 笔记本运行 RViz。本文记录当前已跑通的里程计融合流程，尚不包含 slam_toolbox 或 Nav2 启动。

## 1. 网络和终端安排

笔记本 Wi-Fi 上网，有线接口共享网络到树莓派。当前地址：

- 笔记本有线接口：192.168.137.1
- 树莓派 eth0：192.168.137.100
- ROS_DOMAIN_ID：30；ROS_LOCALHOST_ONLY：0

从笔记本连接树莓派：
```bash
ssh admin@192.168.137.100
```
每个运行树莓派节点的终端都可分别通过 SSH 登录。运行中的节点会占用终端，保留其运行，在其他终端执行下一步。

| 终端 | 运行位置 | 用途 | 是否必需 |
| --- | --- | --- | --- |
| A | 树莓派 | IMU 采集 | 必需 |
| B | 树莓派 | base_link → imu_link 安装 TF | 必需；已有机器人模型发布时省略 |
| C | 树莓派 | STM32 串口桥和 EKF | 必需 |
| D | 树莓派 | 检查话题、频率和 TF | 按需 |
| E | 树莓派 | 雷达采集 | 显示雷达时需要 |
| F | 树莓派 | base_link → laser 安装 TF | 雷达加入 odom 视图时需要；已有 TF 时省略 |
| G | 笔记本 | 里程计 RViz | 可视化时需要 |
| H | 笔记本 | 独立 IMU 姿态视图 | 可选 |

如果之前配置过 Cyclone DDS，继续在各终端加载已经验证过的 DDS 环境。两台机器应使用一致的 RMW 设置，各自网卡绑定配置应正确。下面未额外设置 DDS 变量。

## 2. 首次更新代码和编译（日常运行跳过）

推荐先在两台机器分别克隆仓库到 ~/RosCar，按仓库 README 编译。Ubuntu 开发主机当前仓库实际位于 /mnt/data/linuxproject/RosCar；下文 ~/RosCar 是常规克隆位置，应替换为实际路径。后续更新优先使用 git pull --ff-only。

如果临时通过 scp 同步，在笔记本仓库目录运行以下命令：
```bash
ssh admin@192.168.137.100 'mkdir -p ~/RosCar/pi_ws/src'
scp -r ./pi_ws/src/learm_bridge \
  ./pi_ws/src/icm20948_ros2 \
  admin@192.168.137.100:~/RosCar/pi_ws/src/
```

在树莓派终端安装依赖并编译：
```bash
sudo apt install ros-humble-robot-localization python3-serial
source /opt/ros/humble/setup.bash
cd ~/RosCar/pi_ws
colcon build --symlink-install --packages-select learm_bridge icm20948_ros2
source install/setup.bash
```

雷达单独放在仓库 ~/RosCar/lidar_ws，不需要搬到 ~/RosCar/pi_ws。若需要重新编译雷达：
```bash
source /opt/ros/humble/setup.bash
cd ~/RosCar/lidar_ws
colcon build --symlink-install --packages-select ldlidar --cmake-args -DBUILD_TESTING=OFF
```

## 3. 树莓派终端 A：IMU

GPIO 物理 3/5 对应 /dev/i2c-1。默认地址 0x68。
```bash
source /opt/ros/humble/setup.bash
source ~/RosCar/pi_ws/install/setup.bash
export ROS_DOMAIN_ID=30
export ROS_LOCALHOST_ONLY=0

ros2 launch icm20948_ros2 imu.launch.py
```
启动时保持 IMU 静止约 3 秒进行零偏校准。若地址为 0x69，启动命令增加 address:=105。

保持运行。/imu/data 和 /imu/data_raw 应接近 100 Hz。

## 4. 树莓派终端 B：IMU 安装 TF

下面是当前用于连通验证的零变换。它只有在 IMU 的 X 朝车头、Y 朝左、Z 朝上时才表示正确安装方向。最终需填写实测位置和方向，不要把水平放置直接等同于零旋转。
```bash
source /opt/ros/humble/setup.bash
source ~/RosCar/pi_ws/install/setup.bash
export ROS_DOMAIN_ID=30
export ROS_LOCALHOST_ONLY=0

ros2 run tf2_ros static_transform_publisher \
  --x 0 --y 0 --z 0 \
  --roll 0 --pitch 0 --yaw 0 \
  --frame-id base_link --child-frame-id imu_link
```
位置单位为米，角度单位为弧度。当前只融合角速度，零平移可用于初步验证；安装旋转仍需正确。

当 IMU 的 Z 轴朝上且只有水平安装旋转时：

| IMU X 正方向 | yaw |
| --- | --- |
| 车头 | 0 |
| 车体左侧 | 1.570796 |
| 车尾 | 3.141593 |
| 车体右侧 | -1.570796 |

如果 robot_state_publisher 已经发布这条 TF，不要重复发布。保持此终端运行。

## 5. 树莓派终端 C：底盘串口和 EKF

停止旧的串口桥、wheel_monitor 或其他占用 STM32 串口的程序，再执行：
```bash
source /opt/ros/humble/setup.bash
source ~/RosCar/pi_ws/install/setup.bash
export ROS_DOMAIN_ID=30
export ROS_LOCALHOST_ONLY=0

ros2 launch icm20948_ros2 chassis_ekf.launch.py
```
默认 STM32 串口：
```text
/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0
```
如路径不同，用实际设备替换：
```bash
ros2 launch icm20948_ros2 chassis_ekf.launch.py port:=/dev/ttyUSB0
```
以上两种启动命令二选一。组合启动已包含串口桥和 EKF，不要再启动其他串口桥或 EKF。

该组合自动设置桥接 publish_tf=false，由 EKF 唯一发布 odom → base_link：

- /odom：原始轮式里程计，twist 位于 base_link。
- /imu/data：IMU 数据，使用 Z 轴角速度参与融合。
- /odometry/filtered：融合里程计，约 30 Hz。
- EKF 融合轮式 vx、vy、wz 和 IMU wz，保留麦轮横移。
- 编码器积分位姿、IMU 相对航向和加速度暂不参与融合。

保持此终端运行。

## 6. 树莓派终端 D：检查（按需）

```bash
source /opt/ros/humble/setup.bash
source ~/RosCar/pi_ws/install/setup.bash
export ROS_DOMAIN_ID=30
export ROS_LOCALHOST_ONLY=0

ros2 node list
ros2 topic info /odom
ros2 topic info /imu/data
ros2 topic info /odometry/filtered
```

频率检查逐条执行，每条用 Ctrl+C 退出后再执行下一条：
```bash
ros2 topic hz /odom
ros2 topic hz /imu/data
ros2 topic hz /odometry/filtered
```
IMU 约 100 Hz，融合输出约 30 Hz；轮式话题频率由 STM32 遥测决定。开始的一次话题发现警告不代表失败，随后能持续输出频率即可。

消息检查：
```bash
ros2 topic echo /odom nav_msgs/msg/Odometry --once
ros2 topic echo /imu/data sensor_msgs/msg/Imu --once
ros2 topic echo /odometry/filtered nav_msgs/msg/Odometry --once
```
TF 检查也逐条运行，Ctrl+C 退出当前命令：
```bash
ros2 run tf2_ros tf2_echo base_link imu_link
ros2 run tf2_ros tf2_echo odom base_link
```
静态 TF 显示 At time 0.0 正常。刚启动的一次 Waiting for transform 正常，持续没有变换才需排查。

方向验证：向前时 linear.x > 0，向左横移时 linear.y > 0，逆时针时 angular.z > 0。保持底盘和 IMU 固定安装后再进行比较。

## 8. 树莓派终端 F：雷达安装 TF（与里程计一起显示时需要）

如果还没有机器人模型发布 base_link → laser，应先测量雷达相对底盘的位置与方向。以下为命令模板，不要直接复制占位文字运行：

先在该终端加载环境：

```bash
source /opt/ros/humble/setup.bash
source ~/RosCar/pi_ws/install/setup.bash
export ROS_DOMAIN_ID=30
export ROS_LOCALHOST_ONLY=0
```

再用实际测量值替换下面的占位文字：

```text
ros2 run tf2_ros static_transform_publisher \
  --x 实测X --y 实测Y --z 实测Z \
  --roll 实测横滚 --pitch 实测俯仰 --yaw 实测偏航 \
  --frame-id base_link --child-frame-id laser
```
角度为弧度。该 TF 方向需与 /scan 实际坐标方向一致；不要仅为消除 RViz 报错而假设零旋转。

仅查看扫描形状时，可暂把 RViz Fixed Frame 设为 laser；同时查看扫描和里程计需要完整的 odom → base_link → laser 链。

## 9. 笔记本终端 G：RViz 查看融合里程计

在笔记本本机终端执行，不要在 SSH 到树莓派的终端中启动 RViz：
```bash
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=30
export ROS_LOCALHOST_ONLY=0

ros2 run rviz2 rviz2
```
如尚未安装：
```bash
sudo apt install ros-humble-rviz2
```
查看标准里程计和扫描消息不需要在笔记本编译 IMU 包。

RViz 设置：

1. Global Options → Fixed Frame：odom。
2. Add → Grid，作为地面参考。
3. Add → TF：查看 odom → base_link → imu_link，及雷达安装 TF。
4. Add → Odometry：Topic 选 /odometry/filtered。
5. 再添加一个 Odometry：Topic 选 /odom，用不同颜色比较。
6. Odometry 的 Keep 调大到例如 100，用于保留一段历史位姿箭头。
7. 若查看雷达，添加 LaserScan，Topic 选 /scan，Reliability 选 Best Effort。确保雷达安装 TF 已发布。

Odometry 显示的是位姿箭头序列。移动机器人后才能看到位置变化；当前没有自动发布 nav_msgs/Path 轨迹话题。没有 URDF 时也不会自动出现车体模型。

接入 slam_toolbox 并产生 map → odom 后，才将 Fixed Frame 改为 map。当前无需启动 SLAM 或 Nav2 来查看 EKF。

可在笔记本另开终端，加载同样 ROS 环境后检查：
```bash
ros2 topic list
ros2 topic echo /odometry/filtered nav_msgs/msg/Odometry --once
```

## 11. 常见故障

### 有话题但没有数据
检查相应采集终端是否还在运行、启动日志是否报错。EKF 固定 30 Hz 输出本身不保证两个输入都在更新，需要分别检查 /odom 和 /imu/data。

### TF 检查一直找不到坐标系
在发布端和检查端分别确认：
```bash
echo "$ROS_DOMAIN_ID"
echo "$ROS_LOCALHOST_ONLY"
echo "$RMW_IMPLEMENTATION"
echo "$CYCLONEDDS_URI"
```
检查静态变换：
```bash
ros2 topic echo /tf_static tf2_msgs/msg/TFMessage \
  --qos-durability transient_local --qos-reliability reliable --once
```

### STM32 串口异常
```bash
ls -l /dev/serial/by-id/
sudo fuser -v /dev/ttyUSB0
groups
```
设备路径换成实际设备。确认只有一个桥接节点使用串口，用户属于 dialout 组。

### 笔记本发现不了话题
检查网线地址、两端 ROS_DOMAIN_ID 和 DDS 配置。两端 ROS_LOCALHOST_ONLY 都设为 0。当前网络是树莓派 192.168.137.100 与笔记本 192.168.137.1。

## C++ 学习包（本机离线验证）

新增 `learm_bridge_cpp` 包暂不接入上述 A～H 运行流程。先在笔记本 WSL 中按 [迁移路线](C++迁移路线.md) 执行 Makefile/colcon 构建；产物放在 E 盘项目内的 build/install/log。ROS 2 串口桥节点由你按 [节点练习](../pi_ws/src/learm_bridge_cpp/NODE_EXERCISE.md) 创建，未创建前只有离线 `learm_replay` 可执行程序。

C++ 节点完成并经验证后，才在树莓派选择它替代 Python 桥。两者不能同时占用 STM32 串口或发布同名里程计；EKF 模式下必须关闭桥接 TF。当前没有修改现有组合 launch，也没有在树莓派运行 C++。本机验证范围见 [C++ 适配验证](C++适配验证.md)。

## 12. 停止运行

先让底盘停止运动，再在各运行终端按 Ctrl+C。检查命令 Ctrl+C 只结束当前检查；采集、融合和 TF 发布各自需要在对应终端停止。

日常只验证 EKF 时，常驻 A、B、C 三个树莓派终端，加 G 一个笔记本 RViz 终端；需要雷达时再增加 E 和必要的 F。D 为临时检查，H 为可选姿态调试。
