# 双机部署总览

2026-11-10：现在按设备分为两个工作区。具体命令不再混排在一份长文档中：

- **Ubuntu22.04 Desktop上位机：[host_ws/README](../host_ws/README.md)**。进入host_ws，构建纯显示包，运行RViz与可选IMU姿态显示。
- **树莓派4B：[pi_ws/README](../pi_ws/README.md)**。进入pi_ws，统一编译STM32桥、IMU、雷达；运行采集、里程计、EKF和TF。

两端各自 `git pull --ff-only` 后进入自己的_ws。首次都先按工作区README安装缺失依赖并执行build.sh；不从另一台机器复制build/install。主机和树莓派即使Ubuntu与ROS发行版相同，也可能是不同CPU架构。

## 话题与分工

| 输出 | 发布位置 | 上位机用途 |
| --- | --- | --- |
| /learm/wheel_encoders、/diagnostics | 树莓派桥 | 调试检查 |
| /odom | 树莓派麦轮里程计 | 显示原始轨迹 |
| /imu/data、/imu/data_raw | 树莓派IMU | 可选姿态显示 |
| /odometry/filtered、odom→base_link | 树莓派EKF | 显示融合轨迹与TF |
| /scan | 树莓派雷达 | 显示扫描 |
| base_link→imu_link/laser | 树莓派实测静态TF或模型 | 将传感器数据变换到odom |

ROS2 DDS负责传输，无需额外TCP转发程序。host_ws包不打开串口/I2C，不运行EKF，不发布机器人安装TF；IMU示意视图只发布隔离的显示参考TF。

## 两端环境

分别编辑host_ws/host.env和pi_ws/pi.env；默认ROS_DOMAIN_ID=30、ROS_LOCALHOST_ONLY=0。RMW和DDS配置保留实际两端已验证设置，配置中绝对路径只在所属主机有效。

相同Humble版本不保证网络连通。确认Ubuntu Desktop与树莓派IP/路由正确、允许DDS发现和数据传输、时钟同步。旧Windows共享网络192.168.137.1/100仅是历史记录，不在脚本中硬编码或自动更改。

需要从上位机SSH进树莓派时，登录后的终端属于树莓派端，应进入pi_ws。RViz在Ubuntu本地桌面终端进入host_ws启动。

## 迁移注意事项

雷达源码从lidar_ws/src移入pi_ws/src，ldlidar_driver与ldlidar仍相邻。host_ws新显示包不依赖pi_ws的IMU硬件包。CMake使用自身目录的相对源码路径和标准install目标，launch从ament索引找包，不固定用户名或仓库绝对地址。

新输出分别为install/host_runtime和install/pi_runtime。旧scripts入口兼容保留，但新操作统一使用对应_ws/start.sh。旧scripts/robot.env保留在原位；请把实测值与DDS设置分别迁入新配置。

若拉取时本地修改与目录移动冲突，先保留或提交修改，再处理合并；不要强制重置。旧build/install/log保留为历史产物，不自动清理。原型板真实运行与网络仍需按两端README验收。
