# Ubuntu 上位机 / 树莓派分工与启动脚本

## 1. 两台机器分别运行什么

上位机：用户的 Ubuntu 22.04 Desktop + ROS 2 Humble，运行 RViz。树莓派：Raspberry Pi 4B，按现有记录为 Ubuntu Server 22.04 + ROS 2 Humble，负责全部硬件数据采集、处理与 ROS 发布。两台机器 ROS 发行版一致有利于通信，但架构可能不同，不共享编译产物和 install 目录。

| 功能 | 树莓派 | 上位机 |
| --- | --- | --- |
| STM32 串口、COBS/CRC、原始编码器 | 运行 `learm_bridge`，拥有串口 | 订阅即可 |
| 麦轮里程计 `/odom` | 计算并发布 | RViz 显示 |
| ICM-20948 原始读取、校准、滤波、`/imu/data` | 运行 `imu_node` | 可选显示姿态 |
| EKF `/odometry/filtered` | 运行 robot_localization | RViz 显示 |
| `odom → base_link` | 只由 EKF 发布 | 订阅 |
| `base_link → imu_link/laser` | 发布实测安装 TF，或复用机器人模型 | 订阅，不重复发布 |
| STL06N `/scan` | 运行雷达驱动 | RViz 显示 |
| 主 RViz | 不运行 | 运行 `rviz2` |
| 独立 IMU 姿态示意 | 不必运行 | 可选 `imu_viewer + RViz`，仅显示处理 |
| C++ 迁移学习包 | 节点完成后再考虑替换 Python 桥 | 可离线编译学习，当前不参与实车链路 |

```text
树莓派：STM32 → 串口解码 → 麦轮里程计 ─┐
        ICM-20948 → 校准与滤波 ────────┴→ EKF
        雷达 → /scan；发布全部机器人 TF
                         │
                  ROS 2 DDS / 局域网
                         ↓
上位机：RViz 订阅 /scan、/odom、/odometry/filtered、TF
```

不需要另写 TCP/UDP 转发程序。ROS 2 DDS 在网络允许发现和传输时，负责将树莓派的话题送到上位机。上位机的 RViz 也有 ROS 节点，但不接管设备、里程计或 EKF。

## 2. 首次准备（在对应主机执行，脚本不自动安装）

两台机器各自获取仓库到 `~/RosCar`，或在已有仓库 `git pull --ff-only`，先保留各自未提交工作。下文所有 `~/RosCar` 按实际位置替换。不要将 WSL 的 x86_64 build/install 复制到 ARM 树莓派。

**树莓派终端**：已有 Ubuntu 22.04 / Humble；设备接线、串口与 I2C 权限按原运行手册准备。依赖缺失时才手动安装：

```bash
sudo apt install python3-colcon-common-extensions python3-serial python3-smbus \
  ros-humble-robot-localization ros-humble-tf2-ros
source /opt/ros/humble/setup.bash
cd ~/RosCar/pi_ws
colcon build --symlink-install --packages-select learm_bridge icm20948_ros2
cd ~/RosCar/lidar_ws
colcon build --symlink-install --packages-select ldlidar --cmake-args -DBUILD_TESTING=OFF
```

**上位机本地桌面终端**：已有 Ubuntu 22.04 Desktop / Humble，主 RViz 不需要编译项目包。RViz 缺失时才安装：

```bash
sudo apt install ros-humble-rviz2
```

**两台机器分别准备配置**（已有配置时保留，不覆盖）：

```bash
cd ~/RosCar
cp -n scripts/robot.env.example scripts/robot.env
nano scripts/robot.env
```

配置是本地受信任的 Bash 文件，已被 Git 忽略；两端分别维护自己的绝对路径。启动脚本先读取配置，再加载 Humble 与所需工作区，与你当前所在目录无关。ROS 日志默认写入仓库内 `log/ros`（已被 Git 忽略），可用 `ROS_LOG_DIR` 覆盖。也可用 `ROSCAR_CONFIG=/绝对路径/配置文件` 指定另一份配置。

- 两端 `ROS_DOMAIN_ID=30`、`ROS_LOCALHOST_ONLY=0`。脚本默认保留已导出的值，配置文件中的赋值可以覆盖它们。
- RMW/DDS 采用之前验证过的配置；需要 Cyclone DDS 时，两边先确保插件已安装，再在配置中填写各自主机的 `RMW_IMPLEMENTATION` 和 `CYCLONEDDS_URI`。脚本不会修改 IP、网卡、防火墙或时间同步。
- 当前历史网络为笔记本 192.168.137.1、树莓派 192.168.137.100；Ubuntu Desktop 的实际网卡、IP 和路由需要现场核对，不能假定与 Windows 共享网络相同。相同 ROS 版本不等于网络已经连通。
- 两台机器应保持时钟同步，避免 RViz 因传感器/TF 时间偏差无法显示。本脚本不调整系统时钟。

## 3. 树莓派：推荐一个终端启动采集与处理

修改树莓派配置中的：

```bash
STM32_PORT=/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0
ENABLE_LIDAR=true
USE_EXTERNAL_MOUNT_TF=false
IMU_MOUNT="实测x 实测y 实测z 实测roll 实测pitch 实测yaw"
LIDAR_MOUNT="实测x 实测y 实测z 实测roll 实测pitch 实测yaw"
```

以上带中文的两行是格式示意，**必须替换成各六个数值**：位置单位 m，角度单位 rad，表示 `base_link → imu_link` 和 `base_link → laser`。空值、少值或非法数字会在打开设备前拒绝启动。不要把未测量的安装方向默认为零。如果已有机器人模型持续提供两个安装 TF，设置 `USE_EXTERNAL_MOUNT_TF=true`，让脚本不重复发布；只启用 IMU 时只要求其 TF。

先检查，不启动节点：

```bash
cd ~/RosCar
bash scripts/raspberry_pi.sh all --dry-run
```

检查依赖通过、设备空闲、IMU 静止后启动：

```bash
bash scripts/raspberry_pi.sh all
```

该入口使用一个 ROS 2 launch 管理 IMU、串口桥、EKF、可选雷达和安装 TF。串口桥 TF 固定关闭，只有 EKF 发布 `odom → base_link`。Ctrl+C 由 ROS launch 处理全部子进程。它不是后台服务，不自动开机启动，也不通过 SSH 在别的机器执行。IMU 启动校准时约需静止 3 秒。

只用 IMU+底盘、暂不接雷达：在配置中设置 `ENABLE_LIDAR=false`；此时不要求雷达包或雷达安装参数。主 RViz 的 Laser Scan 可手动取消勾选。

2026-11-10：C++ 底盘桥已完成。`all`/`chassis` 现在支持配置 `BRIDGE_IMPL=python`（默认）或 `BRIDGE_IMPL=cpp`。切换前在树莓派本机编译 `learm_bridge_cpp`，停止旧 Python 组合，再改配置并重新启动；IMU 仍使用 Python。建议先单独检查 C++ `/odom` 和 `/diagnostics`，再接 EKF。

```bash
# 树莓派本机执行，已有ROS/Humble及开发依赖；只编译不启动设备。
source /opt/ros/humble/setup.bash
cd ~/RosCar/pi_ws
colcon build --symlink-install --packages-select learm_bridge_cpp \
  --cmake-args -DLEARM_BUILD_STUDENT_NODE=ON
# 然后在 scripts/robot.env 中设 BRIDGE_IMPL=cpp。
```

C++ 完整启动、参数和 WSL 模拟验证见 [包说明](../pi_ws/src/learm_bridge_cpp/README.md)。上位机 RViz 脚本和话题保持一致。

## 4. 上位机：一个终端启动 RViz

在 **Ubuntu Desktop 本地桌面终端**执行，不要在 SSH 到树莓派的 shell 执行：

```bash
cd ~/RosCar
bash scripts/desktop.sh --dry-run
bash scripts/desktop.sh
```

默认加载 `config/desktop.rviz`：Fixed Frame=`odom`，显示 TF、`/scan`、`/odom` 和 `/odometry/filtered`。LaserScan 使用 Best Effort，兼容常见传感器 QoS。主 RViz 不需要 source 或构建传感器包，不会打开本机 I2C/串口。

独立 IMU 姿态示意是可选功能，需要在上位机另行编译包含 viewer 的 Python 包；不连接本机 IMU：

```bash
source /opt/ros/humble/setup.bash
cd ~/RosCar/pi_ws
colcon build --symlink-install --packages-select icm20948_ros2
cd ~/RosCar
bash scripts/desktop.sh imu-view
```

独立视图使用 `imu_view` 示意坐标系；它不替代机器人安装 TF，不参与 EKF。日常查看融合里程计只需默认主 RViz。

## 5. 树莓派：需要逐模块调试时

不要与 `all` 同时运行。下面每一条长期运行命令各占一个树莓派终端，配置与 ROS 环境由脚本自动加载：

| 命令 | 进程与前置条件 |
| --- | --- |
| `bash scripts/raspberry_pi.sh imu` | 仅 IMU；保持静止校准 |
| `bash scripts/raspberry_pi.sh imu-tf` | 实测 IMU 安装 TF；已有模型发布时不启动 |
| `bash scripts/raspberry_pi.sh chassis` | 串口桥 + EKF；需另有 IMU 与安装 TF |
| `bash scripts/raspberry_pi.sh lidar` | 仅雷达，固定沿用 /dev/serial0、230400 |
| `bash scripts/raspberry_pi.sh lidar-tf` | 实测雷达安装 TF；已有模型发布时不启动 |

所有模式支持 `--dry-run`。采集模式可附加原 launch 支持的参数，例如 `bash scripts/raspberry_pi.sh chassis port:=/dev/ttyUSB0`。`all` 的同名参数以后面的值为准，但安装参数仍由 launch 在启动前校验；TF 模式不接受额外 launch 参数。

## 6. 两端联调与退出

在上位机另一个终端，加载与脚本相同的环境后检查：

```bash
source /opt/ros/humble/setup.bash
source ~/RosCar/scripts/robot.env
ros2 topic list
ros2 topic info /odom
ros2 topic info /odometry/filtered
ros2 topic hz /scan
```

`hz` 用 Ctrl+C 退出后再查其他话题。确认 `/odom` 与 `/imu/data` 持续更新；EKF 自己以 30Hz 输出不能证明输入有效。RViz 看不到扫描时先看 `base_link → laser`、frame_id 和网络发现；只看雷达可临时将 Fixed Frame 改为 `laser`。

退出先让底盘停止运动，再在树莓派采集终端 Ctrl+C，最后关闭上位机 RViz。启动第二组桥或 launch 之前，确认旧进程已退出，避免同一串口或 TF 被重复使用。
